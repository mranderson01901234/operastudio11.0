# Image Editing Integration Options for Imagen4 Outputs

## Overview

This document explores options for giving the LLM tools to edit images generated by Imagen4. We don't need to rely on Imagen4's editing features - instead, we can integrate a separate image processing solution.

---

## Option 1: Use Existing MCP Server (ImageSorcery) ⭐ RECOMMENDED

### What is ImageSorcery MCP Server?

**GitHub:** https://github.com/sunriseapps/imagesorcery-mcp

An MCP server that provides image processing tools via the Model Context Protocol. It's designed exactly for this use case.

### Advantages:
- ✅ **Already built** - No need to implement from scratch
- ✅ **MCP Protocol** - Follows the same pattern as your filesystem MCP server
- ✅ **Standardized** - Uses the same tool interface your LLM already understands
- ✅ **Maintained** - Community project, actively developed
- ✅ **Easy Integration** - Can be added alongside your existing MCP server

### How It Works:

```
User generates image with Imagen4
    ↓
Image stored in imagen-context with ID
    ↓
User: "Crop this image to focus on the face"
    ↓
LLM calls: imagen_crop({ imageId: "current", ... })
    ↓
Tool handler routes to ImageSorcery MCP server
    ↓
ImageSorcery processes image
    ↓
Returns edited image (base64)
    ↓
Updated in imagen-context
```

### Integration Steps:

1. **Install ImageSorcery MCP Server:**
   ```bash
   npm install @imagesorcery/mcp-server
   # OR clone and use as separate process
   ```

2. **Start ImageSorcery MCP Server** (similar to your filesystem MCP server):
   - Can run as separate process
   - Or integrate into your existing MCP server infrastructure

3. **Add Tool Definitions:**
   ```typescript
   // lib/chat/imagen-edit-tool-definitions.ts
   export const IMAGEN_EDIT_TOOLS: ToolDefinition[] = [
     {
       name: "imagen_crop",
       description: "Crop an image to a specific region...",
       parameters: {
         type: "object",
         properties: {
           imageId: { type: "string", description: "ID of image to edit" },
           x: { type: "number" },
           y: { type: "number" },
           width: { type: "number" },
           height: { type: "number" }
         },
         required: ["imageId", "x", "y", "width", "height"]
       }
     },
     // ... more tools from ImageSorcery
   ];
   ```

4. **Route Tools to ImageSorcery:**
   ```typescript
   // lib/chat/tool-handler.ts
   async function executeImagenEditToolCall(toolCall: ToolCall): Promise<ToolResult> {
     // Call ImageSorcery MCP server
     // Similar to how you call filesystem MCP server
   }
   ```

### Tools Available (from ImageSorcery):
- Image cropping
- Resizing
- Format conversion
- Filter application
- Color adjustments
- And more...

### Considerations:
- Need to check if ImageSorcery supports all operations you want
- May need to extend it for custom operations
- Requires managing another MCP server process

## Option 2: Custom MCP Server with Sharp ⭐ MOST FLEXIBLE

### What is Sharp?

**npm:** `sharp` - High-performance image processing library for Node.js

- ✅ **Fast** - Native bindings, very performant
- ✅ **Comprehensive** - Supports all common image operations
- ✅ **TypeScript** - Full TypeScript support
- ✅ **Well-maintained** - Industry standard, actively maintained
- ✅ **Memory efficient** - Streams images, doesn't load full image into memory

### Advantages:
- ✅ **Full Control** - Implement exactly the tools you need
- ✅ **Consistent Pattern** - Follows your existing MCP server architecture
- ✅ **Extensible** - Easy to add new operations
- ✅ **No External Dependencies** - Self-contained

### Implementation Structure:

```
mcp-server-image-editing/
├── src/

│   ├── tools/
```

### Example Tool Implementation:

```typescript
// mcp-server-image-editing/src/tools/image-editing.ts
import sharp from 'sharp';

export class ImageEditingTools {
  async crop(imageBuffer: Buffer, x: number, y: number, width: number, height: number) {
    return await sharp(imageBuffer)
      .extract({ left: x, top: y, width, height })
      .toBuffer();
  }

  async resize(imageBuffer: Buffer, width: number, height: number) {
    return await sharp(imageBuffer)
      .resize(width, height)
      .toBuffer();
  }

  async adjustBrightness(imageBuffer: Buffer, brightness: number) {
    return await sharp(imageBuffer)
      .modulate({ brightness })
      .toBuffer();
  }

  async applyFilter(imageBuffer: Buffer, filter: string) {
    // Implement filters
  }
}
```

### Integration Pattern:

Follow your existing MCP server pattern:

```typescript
// mcp-server-image-editing/src/index.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { ImageEditingTools } from "./tools/image-editing.js";

class ImageEditingMCPServer {
  private server: Server;
  private imageTools: ImageEditingTools;

  constructor() {
    this.imageTools = new ImageEditingTools();
    // ... setup MCP server
  }

  private setupHandlers() {
    this.server.setRequestHandler(CallToolRequestSchema, async (request) => {
      const { name, arguments: args } = request.params;

      if (name === "image_crop") {
        // Get image from imagen-context (via API)
        const imageBuffer = await this.getImageBuffer(args.imageId);
        const result = await this.imageTools.crop(
          imageBuffer,
          args.x,
          args.y,
          args.width,
          args.height
        );
        return { content: [{ type: "image", data: result.toString('base64') }] };
      }
      // ... more tools
    });
  }
}
```

- Need to implement each tool yourself

## Option 3: API Routes with Sharp (Simplest) ⭐ QUICKEST TO IMPLEMENT

### Approach:

Instead of a separate MCP server, create API routes that use Sharp directly. This follows your existing pattern for `imagen_generate`.

### Advantages:
- ✅ **Simplest** - No MCP server to manage
- ✅ **Consistent** - Follows your existing `/api/imagen/generate` pattern
- ✅ **Direct** - Tools call API routes directly
- ✅ **Fast to implement** - Can start with basic operations

### Implementation:

```typescript
// app/api/imagen/crop/route.ts
import { NextRequest, NextResponse } from "next/server";
import sharp from 'sharp';
import { auth } from "@clerk/nextjs/server";
import { getImageFromContext } from "@/lib/imagen/image-resolver";

export async function POST(request: NextRequest) {
  const { userId } = await auth();
  if (!userId) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  const { imageId, x, y, width, height } = await request.json();
  
  // Get image from imagen-context
  const image = await getImageFromContext(imageId, userId);
  const imageBuffer = Buffer.from(image.data, 'base64');

  // Process with Sharp
  const cropped = await sharp(imageBuffer)
    .extract({ left: x, top: y, width, height })
    .toBuffer();

  return NextResponse.json({
    success: true,
    image: {
      data: cropped.toString('base64'),
      mimeType: image.mimeType
    }
  });
}
```

### Tool Handler:

```typescript
// lib/chat/tool-handler.ts

  const response = await fetch(endpoint, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(toolCall.arguments)
  });

  return { /* ... */ };
}
```

### Image Resolution:

```typescript
// lib/imagen/image-resolver.ts
import { getImagenContextForUser } from "@/lib/imagen/storage"; // You'd need to implement this

export async function getImageFromContext(
  imageId: string,
  userId: string
): Promise<{ data: string; mimeType: string }> {
  // Resolve imageId:
  // - "current" → most recent image
  // - "image_123" → specific image ID
  // - "history[0]" → first in history
  
  const context = await getImagenContextForUser(userId);
  
  if (imageId === "current") {
    return context.currentImage;
  }
  
  // ... resolve from history or by ID
}
```

### Considerations:
- Need to store images in database or session storage (currently in-memory context)
- Simpler architecture than MCP server
- Easier to debug and maintain

## Image Storage Consideration

**Current State:**
- Images stored in React context (in-memory)
- Lost on page refresh
- Not accessible from API routes

**For Image Editing, You Need:**

**Option A: Database Storage**
```typescript
// prisma/schema.prisma
model GeneratedImage {
  id        String   @id @default(cuid())
  userId    String
  data      String   // base64
  mimeType  String
  prompt    String
  createdAt DateTime @default(now())
  
  // For edit history
  originalImageId String?
  editPrompt      String?
  editType        String?
}
```

**Option B: Session Storage**
- Store images in Redis/session
- Keyed by userId + imageId
- TTL-based cleanup

**Option C: File System + Database**
- Store images as files (S3, local storage)
- Store metadata in database
- More scalable for large images

**Recommendation:** Start with Option A (database), migrate to Option C if needed.
